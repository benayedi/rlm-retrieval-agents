# Patch history of the document REPL agent harness

The original working directory carried nine `apply_*_patch.py` scripts (kept in
`original/FULLDOC/src/`). Each one rewrote `tools.py`, `run_one.py`, `prompts.py`, `run_experiment.py`, `judge.py`
or `retrieval_server.py` **in place** with `str.replace`, and was run once, by hand, between evaluation sweeps. They
are not part of `src/`: the files in `src/` are the state the patches (and later hand edits) left on disk, which
is the state that produced the results.

## How presence was checked

For every `s.replace(old, new)` in every patch, the distinctive lines of `new` (lines longer than 25 characters that
do not already occur in `old`) were searched for in the corresponding file of `original/FULLDOC/src/`. "Present"
below means those lines are found; "absent" means they are not. Where a patch is present only partly, the later hand
edit is named. The checker is reproducible with a few lines of `ast` (walk the `Call` nodes whose attribute is
`replace`, resolve string constants, compare with the target file).

## State the patches leave that matters for reading the code

- `tools.py` advertises `read_docs(docs, question)` in every search description, and the design-B fixed-k branch
  tells the model to use `llm_query` / `llm_query_batched`; no `read_docs` is installed anywhere
  (`custom_tools()` installs `search`, `search_many`, `grep_docs`, `unread_docs`, `DOCS`, `SEARCH_LOG`).
- `prompts.prologue_id()` hashes `QUERY_TEMPLATE + CONTEXT_NOTE + USER_PROLOGUE` and the design markers only.
- `ToolBox` still has design D, which needs a server mode (`passages`) that no preserved server implements.
