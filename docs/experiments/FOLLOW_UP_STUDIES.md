# Follow-up studies

Work done after the results table ([AGENT_COMPARISON.md](AGENT_COMPARISON.md)), on one question: **can the agent's
search be improved without changing the agent?** Two levers were tried on the document REPL agent: optimising its
prompt (GEPA) and changing what each search returns (a search policy). Around them sit the runs needed to read them:
controls, the FRAMES search cap, the DSPy.RLM ablation behind the choice of library, the run-to-run variation of GPT-5,
and the FRAMES error analysis.

The code is in [`studies/`](../../studies/README.md) (work around an agent) and under the agents (runs that change one
setting of an agent). Every number below is copied from the source named in its row
([results/follow_up/numbers.yaml](../../results/follow_up/numbers.yaml)); this file is generated by
`scripts/docs/make_follow_up_docs.py` from that file and from `experiments/registry.yaml`.

**Judges.** Accuracies are reported with the paper's judge, gpt-4.1 (three votes, official template). The arms first
judged by the served Qwen3.6 model were re-judged with gpt-4.1 on 2026-10-27 and 2026-11-10/11; the Qwen3.6 values are
kept in the tables, marked "superseded", because the original documents quote them. Two studies (ERR-1, FB-1) have
Qwen3.6 verdicts only and are used qualitatively. OBLIQ-Bench is scored by NDCG@10, without a judge.

Sources: **EVIDENCE** = the thesis evidence ledger, section "RQ4: GPT-4.1 re-judge"; **STATUS**, **GEPA_PLAN**,
**BENCHMARKS**, **HANDOFF** = `docs/EXPERIMENTS_STATUS.md`, `docs/GEPA_BROWSECOMP_PLAN.md`, `docs/DATASET_BENCHMARKS.md`,
`docs/HANDOFF.md` of the original repository; **SUMMARY_XLSX** = its `docs/rlm_results_summary.xlsx`; **VERDICTS** =
[`results/follow_up/verdicts/`](../../results/follow_up/verdicts/) of this repository. Numbers are copied, not recomputed.

## Search policy

### SP-1: novelty filter + reranker, BrowseComp-Plus, Qwen3.6, all 830

**Design.** A proxy sits between the document REPL agent and the Reason-ModernColBERT server
([studies/search_policy/src/rerank_proxy.py](../../studies/search_policy/src/rerank_proxy.py)). For each search it takes
the retriever's top 30, drops the documents this run already received (novelty), scores the rest with
Qwen3-Reranker-4B against the **full question** plus the current query, and returns the agent's k. Agent, prompt,
model, caps and judge are those of BCP-29, the control. The policy came out of an offline replay of 19,944 logged
searches (`studies/search_policy/analysis/`). The 830 questions were run in slices (test200, test_rest, pareto,
feedback, rest300) between 2026-10-10 and 10-20.

| Measure | This run | Compared with | n | Test / note | Judge | Source |
|---|---|---|---|---|---|---|
| accuracy, all 830 | 67.5 % (0.6747) | 58.0 % (0.5795), BCP-29 | 830 | won/lost 147/68, McNemar p 7.1e-8 | gpt-4.1 (re-judged 2026-10-27) | EVIDENCE (67.5 vs 58.0); STATUS §5 (rows 16 -> 17: 0.5795 -> 0.6747, won/lost 147/68, p 7.1e-8); VERDICTS bcp/16.json, bcp/17.json |
| accuracy, all 830 | 0.694 | 0.610 | 830 | +8.4 points, t 5.05, won/lost 134/64; gold recall 0.51 -> 0.64 | Qwen3.6 (superseded) | HANDOFF §D |

**Caveats.** The proxy that served the first slice (test200, 2026-10-10) predates cross-request batching and is not
preserved; the slices ran on different days and loads. Launchers are reconstructed from session transcripts.

## Choice of library: the DSPy.RLM ablation

DSPy.RLM (`dspy.RLM`) trailed the snippet REPL agent in the earlier campaign. Two arms on 100 stratified questions
(reweighted to the 775 both earlier runs answered) ask whether that was the library or its configuration.
