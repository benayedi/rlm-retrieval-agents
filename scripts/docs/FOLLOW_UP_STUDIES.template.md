# Follow-up studies

Work done after the results table ([AGENT_COMPARISON.md](AGENT_COMPARISON.md)), on one question: **can the agent's
search be improved without changing the agent?** Two levers were tried on the document REPL agent: optimising its
prompt (GEPA) and changing what each search returns (a search policy). Around them sit the runs needed to read them:
controls, the FRAMES search cap, the DSPy.RLM ablation behind the choice of library, the run-to-run variation of GPT-5,
and the FRAMES error analysis.

The code is in [`studies/`](../../studies/README.md) (work around an agent) and under the agents (runs that change one
setting of an agent). Every number below is copied from the source named in its row
([results/follow_up/numbers.yaml](../../results/follow_up/numbers.yaml)); this file is generated by
`scripts/docs/make_follow_up_docs.py` from that file and from `experiments/registry.yaml`.

**Judges.** Accuracies are reported with the paper's judge, gpt-4.1 (three votes, official template). The arms first
judged by the served Qwen3.6 model were re-judged with gpt-4.1 on 2026-10-27 and 2026-11-10/11; the Qwen3.6 values are
kept in the tables, marked "superseded", because the original documents quote them. Two studies (ERR-1, FB-1) have
Qwen3.6 verdicts only and are used qualitatively. OBLIQ-Bench is scored by NDCG@10, without a judge.

## Search policy

### SP-1: novelty filter + reranker, BrowseComp-Plus, Qwen3.6, all 830

**Design.** A proxy sits between the document REPL agent and the Reason-ModernColBERT server
([studies/search_policy/src/rerank_proxy.py](../../studies/search_policy/src/rerank_proxy.py)). For each search it takes
the retriever's top 30, drops the documents this run already received (novelty), scores the rest with
Qwen3-Reranker-4B against the **full question** plus the current query, and returns the agent's k. Agent, prompt,
model, caps and judge are those of BCP-29, the control. The policy came out of an offline replay of 19,944 logged
searches (`studies/search_policy/analysis/`). The 830 questions were run in slices (test200, test_rest, pareto,
feedback, rest300) between 2026-10-10 and 10-20.

{{RESULT:SP-1}}

**Caveats.** The proxy that served the first slice (test200, 2026-10-10) predates cross-request batching and is not
preserved; the slices ran on different days and loads. Launchers are reconstructed from session transcripts.

### SP-2: reranker only, test200

**Design.** SP-1's proxy with the novelty filter off, on BrowseComp-Plus test200. Separates the two parts of the policy.

{{RESULT:SP-2}}

**Reading.** The reranker carries the gain; the novelty filter adds gold recall but little accuracy.

### SP-3: the search policy with GPT-5 (pilot)

**Design.** GPT-5 (document REPL agent, ColBERT 8192) behind the same proxy on 100 questions: 50 the stored GPT-5 run
(BCP-23) got wrong and 50 it got right. No fresh control: the answers are compared with the stored run's, and the
flips are read against how much plain re-runs of that agent flip (VAR-2).

{{RESULT:SP-3}}

**Caveats.** n = 50 per group. The pilot did not send reasoning effort to the model (only the retry hook was loaded,
KNOWN_ISSUES K3), so it ran at the deployment default, while the stored run may have run at high; the re-run pairs of
VAR-2 ran at medium and are matched only on effort and model.

### SP-4: the search policy on FRAMES (search cap 25)

**Design.** The same proxy (novelty + reranker over BM25's top 30, scored against the question) in front of the FRAMES
BM25 server; agent and caps as FRC-1 (search cap 25, 50 turns), which is the control.

{{RESULT:SP-4}}

**Reading.** Recall rises, accuracy does not: on FRAMES the limit is reasoning after retrieval (see ERR-1).

### SP-6, SP-7: the search policy on OBLIQ-Twitter

## Prompt optimisation (GEPA)

is [agents/document_repl/src/split_runner.py](../../agents/document_repl/src/split_runner.py). Selection score = correct
+ 0.5 × gold recall; reported metric = accuracy on held-out questions.

### GEPA-1: BrowseComp-Plus, run 1 (proportional selection set)

{{RESULT:GEPA-1}}

### GEPA-2: BrowseComp-Plus, run 2 (failure-enriched selection set), held out on test200

{{RESULT:GEPA-2}}

**Reading.** The lead on the selection set came from selection bias and the enrichment; on held-out questions it

evaluations).

### GEPA-3: FRAMES

{{RESULT:GEPA-3}}

### GEPA-4: OBLIQ-Twitter (four runs, Qwen3.8-27B, snippet REPL agent)

{{RESULT:GEPA-4}}

Run 1 was declared void by its successor; runs 2 and 3 corrected its design; run 4 widened the mutable text. No run

### GEPA-5: the pipeline on the GEPA paper's own task (HoVer)

{{RESULT:GEPA-5}}

**Reading.** The same pipeline (driver design, Claude critic, Qwen3.6) reproduces and exceeds the paper's gain on HoVer,
so the nulls above are about the tasks (tuned starting prompts, retrieval-bound errors, noisy long-horizon evaluation),
not about the pipeline.

## Choice of library: the DSPy.RLM ablation

DSPy.RLM (`dspy.RLM`) trailed the snippet REPL agent in the earlier campaign. Two arms on 100 stratified questions
(reweighted to the 775 both earlier runs answered) ask whether that was the library or its configuration.

{{RESULT:DSA-3}}

{{RESULT:DSA-5}}

**Reading.** Lifting the caps and matching the prompt (arm 3) is not enough; matching the models and the search

## Run-to-run variation

### VAR-2: how much a plain re-run of the GPT-5 document REPL agent flips

{{RESULT:VAR-2}}

**Caveats.** The computation was run inline in a Claude Code session and is recovered byte for byte
(studies/run_variation/). The pairs are not identical configurations (e.g. 512- vs 8,192-token ColBERT index); all ran
at medium effort.

**The 17.8 % figure** used in earlier documents is not a measurement between two runs: it was extrapolated from a replay
of the 112 questions one DSPy.RLM run (gpt-5 medium, Reason-ModernColBERT) retrieved gold for but answered wrong, 47 of
which came back correct; that rate, assumed equal in both directions, gives 2 × 0.4196 × 176 / 830 = 17.8 % (original
repository, `docs/rlm_results_summary.xlsx`, sheet Retrieval, section 27). It is an upper bound (the replay ran four
days later). The only identical repeats of that campaign are three runs of 50 questions (sheet Retrieval, section 12).
Neither is migrated (owner's decision, 2026-11-11).
